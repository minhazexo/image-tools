# ImageTools — Architecture

This document describes the architecture of the ImageTools web app, located in `web/`.

## Principles

1. **Local-first**: image bytes never leave the browser. All processing uses Canvas/OffscreenCanvas, including AI-powered background removal via WASM.
2. **Progressive enhancement**: a Web Worker runs the pipeline when OffscreenCanvas is available; otherwise processing falls back to the main thread.
3. **Composable operations**: every tool is expressed as a list of `ProcessingOperation`s, making the engine small and easy to extend.
4. **Static-first**: the app is fully statically generated by Next.js (22 routes: 16 tool routes + home/tools/about/privacy/terms/contact/creator) and installable as a PWA.

> As-built 2026-10-10: `web/src/lib/tools.ts` holds **15** entries; `/flipper` is an alias route reusing `RotatorTool`, so 16 tool URLs. Knowledge graph: `graphify-out/graph.json` (964 nodes, 1935 edges, 75 communities) — see `graphify-out/GRAPH_REPORT.md`.

## Layering

```
App Router pages (src/app/**)           — server components, SEO metadata
  └── Tool components (src/components/tools/<slug>/)
        └── Shared workflow (src/components/processing/tool-workflow.tsx)
              └── Image components (uploader, comparison, download)
                    └── Processing client (src/lib/process/client.ts)
                          ├── Web Worker (src/lib/workers/imageWorker.ts)
                          └── Canvas engine (src/lib/process/engine.ts)
```

Each tool owns its folder: `src/components/tools/<slug>/` holds the tool
component plus only the files that tool alone uses (e.g. `transparent-image/`
colocates `mask-editor.tsx`, `color-to-transparent/` colocates
`eyedropper.tsx`). Every folder has an `index.ts` barrel, so routes keep
importing `@/components/tools/<slug>` unchanged. Shared UI (`processing/`,
`image/`, `download/`, `layout/`, `ui/`) stays shared — never duplicate it
into a tool folder.

### 1. Routes and metadata

- Every page is a static route generated at build time. Server components export `metadata` built by `src/lib/seo.ts` (`buildMetadata`).
- Interactive trees are marked `"use client"`; the only interactive page content lives in client components.
- `/contact` keeps its interactive `<form>` in a dedicated client component (`ContactForm`) so the page itself stays a server component.

### 2. Tool registry

`src/lib/tools.ts` defines the 15 tools with slug, name, description, category, icon, and keywords (`/flipper` reuses the rotator component, giving 16 tool URLs). `HOMEPAGE_TOOLS` selects the highlighted tools on the homepage. Adding a tool = register it here + add a route page.

### 3. State

`src/lib/store/useImageStore.ts` (Zustand) holds:

- `images`: uploaded images shared across tools.
- `queue`: pending items for the batch processor.
- `selectedImageId`: active image.
- `preferences`: theme, last output format, last quality — the only persisted slice (localStorage via `persist`).

Nothing image-related is persisted.

### 4. Processing pipeline

See [image-processing.md](image-processing.md) for the full detail. In short:

1. Validate the file (type, size ≤ 100 MB, pixel budget ≤ ~268 MP).
2. Decode to an `ImageBitmap` (`createImageBitmap`); fall back to `HTMLImageElement` when unavailable.
3. Build an operation list (e.g. `[{ type: "resize", options }, { type: "convert", options }]`).
4. Send `{ id, file, operations, encode }` to the worker; the worker returns a Blob + dimensions + timing.
5. If the worker is unavailable, `processBitmap` runs the same pipeline on the main thread.
6. Compose a `ProcessingResult` (blob, URL, savings, timing) and revoke URLs when replaced.

### 5. Styling

Tailwind CSS with CSS variables in `src/app/globals.css` (HSL tokens) that switch on a `.dark` class. The `cn()` helper in `src/lib/utils/cn.ts` merges class strings (small, dependency-free).

## Extending the app

**Add a new tool**

1. Create `src/components/tools/<slug>/` with the tool component + an `index.ts` barrel (`export * from "./<slug>"`); colocate only single-use files there.
2. Register it in `src/lib/tools.ts`.
3. Add `src/app/<slug>/page.tsx` exporting `metadata` (dynamic-import `@/components/tools/<slug>`, `ssr: false`).

**Add a new engine operation**

1. Add the option types to `src/lib/types.ts` (`ProcessingOperation` union).
2. Implement the step in `src/lib/process/engine.ts` (`processBitmap`).
3. The worker/client pass operations through unchanged.

## Build notes

- `next.config.mjs` sets `optimizePackageImports: ["lucide-react"]` plus long-cache headers for `/_next/static` + images/fonts, `max-age=0` + `Service-Worker-Allowed: /` for `sw.js`, and daily cache for `manifest.webmanifest`.
- Build output is fully static (`○` for every route).
